- 四輪 arena（2026-10-18）共跑了 19 次玩家，用到 Codex（gpt-6.1-sol、gpt-6-luna）、Claude Code（Sonnet 5.5、Haiku 5.5）、pi（Kimi-K3）。每一輪都達到「能用」。

## 試玩方式

- 平台：`arena-server` worktree 的本機 dev server，每一輪用當時最新的 `main`（f9b1d98、1820be2、4ce4b10、baabaa7）。
- 玩家：用 coordinator 的 arena 腳本在命令列跑（`claude -p`、`codex exec`、`pi -p`）。
  - 每個玩家各有一個 repo 外的 git 資料夾，skill.md 裝成專案層級的 skill。
  - HOME 是假的，裡面只有登入檔的連結，所以讀不到 Dev VM 規則和使用者的 skill。第 1 輪還沒這樣隔離，見下面「第 1 輪」。
- 給玩家的話：各家的 skill 叫用語法加一句「請你幫我玩一局德州撲克」。第 4 輪改用別的說法，測安裝和其他情境。
- 跟 agent-playtest skill 的差異：
  - 名字不是我們給的，由玩家照 skill.md 自己取，所以取名本身也被測到。
  - 除了 skill 列的三種 agent，另外加了 pi。
- 回顧：打完後在同一個 session 問五題，原文收在各輪的報告裡。
  - 哪一步最卡？
  - 說明書哪裡要猜？
  - 哪個回應不知道下一步？
  - `note` 和 `watch_url` 有沒有用、有沒有交給主人？
  - 最想改的三件事？

### 怎麼判讀

- **沒有對手的玩家。** 第 3、4 輪的 sol 是刻意讓人數成單數，所以沒有打到。
  - 第 3 輪：它照當時的說明書等了約 10 分鐘就放棄。這個問題由 T30 修正。
  - 第 4 輪：它等了 198 秒後回報主人，列出三個選項，沒有自己決定。
  - 兩次都是照說明書做的，不算「沒打完」。
- **回報主人不算「停下來問人」。** 第 4 輪 sol 回報主人，是 skill.md 要它做的，不算這一項。
- **第 1 輪不是乾淨的結果。**
  - Codex 停下來問了 1 次，原因是 Dev VM 的全域規則要它「呼叫外部服務前先問」，不是平台的問題。
  - pi 用錯叫用語法，沒讀到 skill，改讀 repo 裡的內部規格。
  - 從第 2 輪起改成隔離跑，這兩個問題都沒再出現。
- **第 2 輪的錯誤是 luna 自己抄錯。** 它每一步都重貼 token，有 2 次打錯，所以沒達到「好用」的每場 ≤ 1。
  - T27 教 agent 把 token 存成檔案。
  - T28 把 `invalid_token` 的 hint 改成先核對原本的 token。
  - 第 3、4 輪就沒有人再抄錯 token。
- **第 4 輪 luna 的 1 次錯誤。** 它把動作包成 `{"action":{...}}`，看了 hint 後下一次就對了，在「好用」門檻內。
- **`pnpm playtest` 的第一個請求有沒有對沒有數。** 指令只看平台結果。兩次都沒有收到任何錯誤回應，所以第一個請求也是對的，只是沒有特別計算。

## `pnpm playtest`

T14 要的自動化版本：`scripts/playtest.sh`。

- 在 VM 上跑，不是在容器裡，因為容器裡沒有 `claude`、`codex`，也沒有登入檔。
- 隔離方式跟 arena 一樣，用 agent-playtest skill 的那一句（「用名字 X 去排一局」）。名字由腳本給，每次都不同。
- 結果只看平台 API：
  - 要有兩個名字之間已經打完的對局；
  - 兩邊在整場的最後一個動作都是自己做的，不是伺服器代打；
  - 兩個 agent 都要正常結束。
- 本機 worktree 跑了 2 次，都 exit 0：

| 次 | 對局 | 結果 | 手數 | 錯誤 | 超時 |
| --- | --- | --- | --- | --- | --- |
| 1（作者） | `smoke-claude-wg7bli` 對 `smoke-codex-wg7bli` | Codex 勝 63 : 17 | 10 | 0 | 0 |
| 2（verifier） | `smoke-claude-1whb83` 對 `smoke-codex-1whb83` | Codex 勝 80 : 0 | 4 | 0 | 0 |

- 兩次的紀錄裡，玩家都沒有讀到 Dev VM 規則或使用者的 skill。
- 兩次都沒有指定模型，用的是兩個 CLI 各自的預設模型。
- 還沒放進 CI：CI 需要 Claude Code 和 Codex 的登入憑證，目前由人或 agent 在 VM 上手動觸發。

## 提案：做了什麼

「來源」的 R1～R4 是第 1～4 輪；#n 是該輪報告提案表的編號（第 2 輪用「第 1、2 輪合併提案」的編號）。

| 提案（來源） | 怎麼處理 | ticket |
| --- | --- | --- |
| `matched`／`join` 帶對手名字和設定；給主人一個觀戰連結；`note`（R1 #5，E5） | `opponent_name`、`settings`、`watch_url`、`note` | T23 |
| 知道名字就能重叫 queue 拿走別人的座位（T12 的漏洞；斷線後同名重排拿回同一場要靠它才安全，R1 #3） | 排隊必帶 `queue_key` | T26 |
| 一局是什麼、沒給名字怎麼取、流程要自己拼（R1 #1、#2；R2 #1） | skill.md 開頭的「Quick start」與取名規則 | T27 |

第 4 輪驗到的效果：
- 自己安裝 skill 後打完一場；
- 開房邀請朋友；
- 沒有對手時回報主人；
- 程序被砍掉後，從 `.casino/` 的檔案接回同一場打完。

四種情境都過了。

## 提案：決定不做

| 提案（誰提） | 為什麼不做 |
| --- | --- |
| SSE、WebSocket 推播，或「等到輪到我才回」（R2、R3 pi） | 違反「只用 curl」；`wait` 本來就會等到輪到你，最多 30 秒 |
| 官方 SDK、完整機器人或「一輪回合」小腳本（R1、R2 pi；R2、R3 Sonnet、luna） | 違反只用 curl 的精神。T27 改成從檔案讀 token 後，手動 curl 已經夠順 |
| `?compact=1` 精簡回應（R2 pi） | 沒有觀察到 context 不夠用 |
| `actions` 直接等到下一個狀態才回（R2 Sonnet） | 會改變 `actions` 的語意和逾時行為 |
| `wait` 多一個 `you_won` 欄位（R3 Sonnet） | 跟 `stack_changes` 重複 |
| 每個回應都帶第幾手、還剩幾手（R3 Haiku） | `hand_number` 和 `settings.hands` 已經在回應裡 |
| 排行榜標出 bot、標出不計分的場次（R3 Sonnet） | house-bot 本來就不上排行榜 |
| 區分顯示名稱和玩家身分（R2 sol） | 違反「不註冊」。改成讓 agent 取不會撞名的名字（T27，第 4 輪的問題見 T32） |
| Haiku 的 note 還是英文（R3） | 說明書已經寫了，這是小模型遵循指令的問題 |

## 還剩什麼

1. **第 4 輪的說明書與 hint 問題：見 T32。**
   - 名字照抄範例；
   - `watch_url` 沒存檔，接回後交不出來；
   - matched、join、開房的 hint 沒提醒交出 `watch_url`；
   - 安裝說明只有全域路徑；
   - `stack_changes` 和盲注的關係；
   - 私人房間 5 分鐘就取消；
   - `match_over` 沒附網頁連結。
2. **還沒演練的。** 下一輪 arena 再做：
   - chaos 測試房（casino-api skill A11 的環境預設）；
   - 兩邊同時斷線。
   - 第 1 輪 pi 斷線接回是靠運氣，第 4 輪接回時對手是 house-bot。兩邊都是真 agent、其中一邊當掉的情況還沒試過。
3. **`pnpm playtest` 還沒放進 CI**，原因見上面。
4. **不歸平台管的。**
   - agent 的牌力判斷會錯，例如 pi、Haiku、luna 都寫錯過牌型。觀戰頁和對局紀錄讓主人自己核對。
   - pi 第一次用專案 skill 時，會問要不要信任資料夾。T32 會在安裝說明裡提醒。
