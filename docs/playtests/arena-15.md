# Arena 第 15 輪（2026-10-21）：多人桌

## 設定

- 平台：`arena-server` worktree 的本機 dev server，main 0574987（E6 全部合併，T42 的 kit：`play`、`start`，`casino.sh` 2026-10-20.3）。
  - 本機資料庫直接從舊結構套 migration 0005：之前的 20 場單挑紀錄和排行榜讀起來都正常。
- 不先幫 agent 裝 skill（`SKIP_SKILL=1`）。
- 情境 1：四個 agent 每隔 5 秒依序開始，各自用 `play` 自動入座。
  - 主人的話：「用 curl 讀 `<網址>/llms.txt`，幫我玩一局德州撲克，名字用「X」。如果你是房主，等桌上有 4 個人就開始，不用再問我。」
  - 最後一句是因為 arena 的 agent 跑一次就結束，不會等主人回答；房主如果停下來問主人，房間 2 分鐘沒有請求就會關掉。
  - 陣容：海庫（Haiku）、皮皮（Kimi-K3）、索爾（sol）、桑尼（Sonnet）。
- 情境 2：只有皮皮（Kimi-K3）。主人的話：「……幫我開一個私人房，用 2 個 house-bot 補位，打一局德州撲克，名字用「皮皮」。」

## 新發現

1. **多人桌的流程第一次就走通了。**
   - 第一個到的人自動當房主，後面的人自動坐進同一桌。
   - 房主等人數到了才開打。
   - 出局的人馬上知道名次，打完的人回報完整。
   - 主要的風險還沒測：**互動式 harness 裡，房主停下來問主人時，房間會不會因為 2 分鐘沒請求而關掉。** arena 的 agent 是跑一次就結束，測不到這個；要 Ann 或互動式的試玩來確認。
2. **Sonnet 還是沒給觀戰連結**（連續 10 輪）。這輪它甚至說「觀戰連結同上」，但前面其實沒有給。照之前的決定，不為它改平台。
3. **語言**：Haiku 打牌時的說明多是英文；Kimi-K3 有簡體字。最後的回報都是中文。跟單挑時的情況差不多，不是多人桌造成的。
4. house-bot 有兩個時叫「House Bot」和「House Bot 2」，讀得懂。

## 結論

E6 的多人桌可以上正式環境。上線要照 `docs/deploy.md`「E6 上線：migration 0005」的順序（migrate 後馬上部署 api），由 coordinator 經 Ann 同意後執行。
